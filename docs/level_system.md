# 关卡系统设计 v0.2 — 行业 DLC × 关卡

> 让陪练系统像游戏一样：**选行业（DLC）→ 选关卡（阶段）→ 打关 → 通关/失败 → 复盘**。
> 配套：`01/15_剧本库`（关卡内容）、`02/16_台词数据库`（台词）、`18_复盘报告模板.md`（复盘）。
> 日期：2026-08-02 ｜ 状态：v0.2（关卡系统 v1）

## 一、总体架构

```
启动
 ├─ ① 选择行业 DLC
 │    ├─ 制造业（DLC-01）✅ 已上线
 │    └─ 商学院招生（DLC-02）🚧 规划中（下一个）
 │         └─ （未来）更多行业……
 ├─ ② 选择关卡（该 DLC 内）
 │    ├─ 关卡 1-1：第一次正式面谈（单人）✅
 │    ├─ 关卡 1-2：第二次现场会议（三人）✅
 │    ├─ 关卡 1-3：试跑期回访（规划）
 │    └─ （按 DLC 扩展）
 ├─ ③ 开始打关（多回合，教练判定，语音/文字双轨）
 ├─ ④ 结局：✅ 通关 / ❌ 失败（阈值判定）
 └─ ⑤ 关卡复盘报告（无论胜负，统一输出）
```

## 二、关卡元数据（每条关卡一份）

| 字段 | 说明 | 示例（关卡 1-2） |
| --- | --- | --- |
| 关卡 ID | DLC-序号 | `DLC01-L02` |
| 名称 | 场景名 | 第二次现场会议（方案会） |
| 前置条件 | 需先通关的关卡 | 关卡 1-1（有基础信任） |
| 角色 | 客户角色与数量 | 张总 + 老赵 + 老王（3 人） |
| 目标 | 本关的胜利条件 | 张总支持度 ≥+3 且至少一人 ≥+1 |
| 结局 | 通关/失败/分支 | ③全支持 / ②有条件推进 / ①暂缓=失败 |
| 语音 | 各角色 voice/rate | 见 `16_台词数据库_三人.json` |
| 理论主题 | 本关主练的方法 | 多角色异议处理、给定位、影响链 |

## 三、失败判定机制（正式版）

> 用户认可"提醒三次后仍不正确提问 = 判定失败"，正式化为两条阈值：

| 规则 | 阈值 | 触发 |
| --- | --- | --- |
| 红线累计 | ≥2 次 | 介绍产品 / 逼单 / 被拒后补证据 → **提前收场**（走"帮不了/暂缓"结局，视为失败） |
| 关键节点未正确提问 | 同一节点教练提示 3 次仍未修正 | 如：被拒后仍解释、该问动机时仍介绍 → **判定失败**（直接进入复盘） |

失败不等于练习无效——失败后**强制进入关卡复盘**，明确"差在哪、怎么改、理论依据"，然后可**重打本关**（难度不变）或**降级重打**（换 V3 热情开局/减少角色）。

## 四、DLC 扩展方法（新行业怎么加）

1. 建 `剧本库_<场景>.md` + `台词数据库_<场景>.json`（复制现有模板）
2. 填关卡元数据表（上表）
3. 指定各角色 voice（edge-tts 可用声线见脚本注释）
4. 在 `README.md` 关卡表登记 → 即可被"关卡选择器"选用
5. 每个 DLC 需过一遍"教练试跑"验证判定表合理性
